# 04 — Protocollo Evaluation (5 utenti)

Metodo: think-aloud su walkthrough offline (Home→Roadmap→Topic→Quiz→Reward→Boss win/lose→Continue) + questionari SUS (usabilità), IMI (motivazione: interesse/divertimento, competenza percepita, pressione/tensione), GEQ-core (esperienza di gioco: flow, sfida, affetto positivo/negativo). Ogni sessione ~25 min: 5 briefing, 15 task, 5 questionari.

## Task misurati (KPI)

| # | Task | Successo | KPI |
|---|---|---|---|
| T1 | Primo avvio → menu senza errori | 5/5 | crash 0 |
| T2 | Trovare topic sbloccato e aprirlo | 5/5 | tempo mediano <60s |
| T3 | Completare quiz (soglia 80%) | ≥4/5 passano | comprensione soglia (4/5 risposte giuste) |
| T4 | Scegliere 1 reward su 3, ritrovarla in inventory | 5/5 | errori re-claim 0 (guard 1/topic) |
| T5 | Boss fight fino a win o lose + retry | 5/5 | comprensione soglie boss (≥3/5 le notano), frustrazione retry ≤2/5 |
| T6 | Logout/login secondo utente: progressi separati | 4/5 | comprensione save-per-utente |
| T7 | Profilo: coerenza XP HUD vs classifica/card Hub | 4/5 | nessuno segnala numeri diversi |

## Cosa validano

- CD2: soglia 80% percepita come equa? Skip rimosso rimpianto da qualcuno?
- CD3/CD6: scelta reward significativa? Boss-gate motivante?
- CD8 rimosso: nessuno chiede il timer indietro? (se ≥2 lo chiedono, rivalutare)
- CD4: save-per-utente compreso? Badge profilo trovati?
- Bug aperti dalle note: preview reward sufficiente? Victory "troppe reward"? Override "Done" scoperto per caso?

## Output

Tabella per utente (task ok/ko, tempi, SUS/IMI/GEQ, citazioni), 3 fix prioritari, paragrafo GamiDOC cap7_valutazione.
