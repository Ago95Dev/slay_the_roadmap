\chapter{Architettura (rimando)}
\label{g:arch}
Per l'architettura software completa (3-layer Provider, tabelle
file $\rightarrow$ responsabilità, modello di dominio, repository, flussi UI,
integrazione Hub, verifica P0, debiti) si veda il documento gemello
\texttt{specifica.pdf}. Qui si fissa solo il vincolo di design: ogni regola
di gamification deve corrispondere a una \textit{action} Hub
(\texttt{complete\_quiz}, \texttt{unlock\_topic}, \texttt{boss\_hit},
\texttt{earn\_card}) così che il GamiDOC resti la fonte di verità dei
parametri (soglie, danni, HP, costi).
